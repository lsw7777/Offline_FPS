## 【严重 BUG 修复】鼠标不能转视角 / 左键不能开火

- 症状：真窗口里视角被锁死在初始朝向，左键不开火。
- **根因（本轮设置面板改动引入的回归）**：上一轮为了修"右上角按钮跑到屏幕外"，把 HUD 根 `Control` 的 `size` 设成整个 viewport，但 **`mouse_filter` 仍是默认的 `STOP`** → 这块全屏 HUD 像透明玻璃，吞掉了所有鼠标事件：
  1. `InputEventMouseMotion` 被 GUI 消费 → `_unhandled_input` 收不到 → 视角不转；
  2. `get_viewport().gui_get_hovered_control()` 永远返回 HUD → `fire()` 的守卫直接 return → 左键不开火。
- **为什么无头测试全绿却漏掉**：无头环境没有光标，`gui_get_hovered_control()` 恒为 null，bug 只在真实窗口出现。教训：**涉及光标/命中的逻辑必须用真实窗口跑一次**。
- **修复**：
  1. HUD 根 `mouse_filter = Control.MOUSE_FILTER_IGNORE`（子控件独立命中，设置按钮/面板仍可点）；所有 `_mk_label` 也设 IGNORE。
  2. 视角旋转从 `_unhandled_input` 改到 **`_input`**（GUI 之前的阶段，任何全屏控件都吞不掉），仍用 `mouse_mode == CAPTURED` 作门槛。
  3. 开火守卫改为显式 `ui_blocked` 标志（HUD 发 `ui_state_changed(open)` → main 设置 `ws.ui_blocked`），并保留"鼠标未捕获且悬停在控件上则不开火"的兜底；不再依赖 hover 判定单独成立。
- **验证**（关键）：用**非无头真实窗口**跑集成测试 → `mouse_mode=2`(CAPTURED)、`yaw 0.000 → -0.384`（120px × 0.0032 完全吻合）、`INTEGRATION PASS`。这证明视角与开火链路都恢复。
- 集成测试新增回归断言：`hud.mouse_filter == MOUSE_FILTER_IGNORE`、`settings_button.mouse_filter != IGNORE`、鼠标 motion 后 yaw 必须变化（仅在 mouse_mode==CAPTURED 时断言，无头自动跳过）。
